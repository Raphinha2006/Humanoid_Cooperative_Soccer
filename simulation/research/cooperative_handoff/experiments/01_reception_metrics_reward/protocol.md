# 01 — 接球指标、任务可行性与奖励验证

日期：2026-11-11。状态：**计划修订完成，评估器和新奖励尚未实现。** 本文件不表示新实验已通过。工程初值见同目录 `design.yaml`，须在新训练前标定和冻结。

00阶段保留原协议、预算、指标与检查点选择。新增历史分析标为事后诊断，不改写旧主指标。当前发送方冻结，不能把退化归因于双方共同学习。

## 问题与实施顺序

先证明机器人能接住可重放的运动来球，再判断世界模型是否扩大接球能力范围，最后研究发送方如何适应接收方变化。顺序为：评估器正确→任务可行→奖励对齐→WM控制价值→能力图扩大→连续协作。

“连续控球保持时长下降”不能直接推断停球变慢，也不能单独定位控制问题；它可能受触球、位置、速度或朝向影响。所有分项分别记录。

## 1. 两种时间严格分开

- `time_to_control_s`：从首次有效接触到首次稳定控球区间的起点，**越短越好**。条件连续满足0.10 s后才确认，另存确认时刻。
- `max_control_duration_s`：接触后固定2.0 s观察窗内，控球条件成立的最长连续时长，**越长越好**。另报位置、低速、朝向与直立各自成立的时长。

有效接触须来自球与接收方允许部位的MuJoCo接触力，保存接触几何体和时刻。脚部名单先与模型核验；旧的任意接收方部位触球作为兼容诊断，几何接近不能代替接触。

稳定控球条件包括身前区域、球的世界速度和相对接收方速度、球高度、面对面与不跌倒；具体工程阈值可配置，不称官方标准。

主达成事件要求：接触后1.0 s内开始一段连续至少0.8 s的合格控球，并在观察窗内不倒地；完整记录该段起点和确认时刻。0.10 s确认只用于早期停球耗时诊断，不替代0.8 s的稳定保持验收。

### 失败、删失与分母

- 未触球时耗时为null；触球后未停住保存右删失/失败标志，不能记0秒或删除失败后只报成功耗时。
- 同时报告全部预定案例的达成率、失败率、累计达成曲线；条件耗时必须附触球率、成功率和样本数。
- 可另报全部案例的有界完成耗时：从释放计时，成功取上述0.8 s主达成事件的确认时刻，失败取完整任务时限。它是失败惩罚后的比较分数，不冒称真实停球耗时。
- 未触球时保持时长计0；触球案例均观察完整2.0 s，必要时延长仿真，避免结束时间造成比较偏差。
- 接触前与接触后100/300 ms球速、相对位置、朝向与跌倒逐回合记录。自然滚停、慢来球和无接触单列。

## 2. 四层指标与事件漏斗

| 层次 | 指标 |
|---|---|
| 接近与触球 | 有效触球率、首次触球位置误差与部位 |
| 接球质量 | 停球耗时、触球前后球速、相对位置 |
| 控球稳定性 | 固定窗口连续保持时长、朝向误差、跌倒率 |
| 完整协作 | 旧严格接球率、再次传出率、连续2/5/10次交接率及交接次数 |

按释放→发送/进入测试区→有效接触→稳定控制→再传出→队友接稳记录有序事件。全部尝试的无条件比例和各阶段条件比例并列。旧日志中的非嵌套统计不能直接相除重建漏斗。

WM另测冻结轨迹在接触前/中/后的误差，以及真实动作扰动与模型收益变化的方向/排序一致性。位置RMSE和想象回报不能替代控制能力。

## 3. 从受控接球到完整协作

**受控来球。** 暂时分离发送方决策，保持面对面参考方向。一次性设置物理释放初态，不在运动中把球拉向机器人。保存qpos/qvel、控制器记忆、球旋转、物理配置和案例哈希。该测试不要求发送方真实触球，不能冒称完整双机器人传接球。

冻结原生技能、共同起点、已完成组最终检查点，在同一案例上比较。最简单来球若无可行示例，先查技能接口、来球设置与动作权限；没有示例不等于数学上的不可行，也不能据此无限调奖励。

**能力图。** 固定释放速度×横向目标偏移网格，同时记录上游固定截面的实测来球速度。不能根据某策略真正碰到的球重新分箱作主排名，否则会筛除它接不到的球。设计初值为5×5格、每格16个开发案例（400），独立开发复核每格64个（1600），先少量核验释放与接触检测，再标定并冻结。

训练从中央低难度来球逐步扩大范围；评估始终保留完整难度网格与固定权重。课程提高的候选门槛为简单层连续3次开发评估达到70%稳定控球达成率，须在训练前冻结。

**两机器人。** 先冻结发送方，再让发送方适应接收方能力，最后角色交换与连续互传。发送失败计入完整任务分母，不只保留好传球。严格成功率继续作最终验收之一。

## 4. 奖励先验证再投入长训练

详细操作见[奖励验证](reward_validation.md)。当前奖励主要鼓励球靠近身前与世界速度小，未显式定义接触、连续保持、面对面和再次传出。这是目标可能错配的证据，不是已证明的退化原因。

建立自然滚停、无接触靠近、擦碰弹走、背身挡球、倒地压球、慢来球、反复轻触、接稳后永久不传，以及正常接稳/接稳再传的轨迹库。独立标注物理事件，逐项分解奖励；在相同完整时限和折扣下检查排序、奖励累计上限与刷分反例。

候选奖励采用一次性稳定控制/完成交接事件、有界进度塑形和动作/姿态约束。每阶段正奖励有上限；达到保持目标后转向下一阶段，避免永久持球刷完整协作分。具体权重在轨迹审计后、短训练前冻结，旧奖励对照保留。

若用 `gamma*Phi(z_next)-Phi(z)` 塑形，增广状态须包含阶段/历史/计时器，处理终止势值并保持折扣一致。相应MDP下的策略保持性质不保证基础目标正确，也不保证近似WM梯度正确。

真实接触和保持事件依赖历史；当前160维物理状态接口未包含完整任务记忆。真实仿真使用接触力与状态机；WM想象须先验证事件预测和任务记忆，不能读取未来真值。软代理与硬物理验收分开报告，检查校准、误报和被利用风险。

## 5. 执行清单与放行条件

1. **E1 评估器。** 实现逐回合事件、两种时间、失败/删失与固定窗口；用已知事件时序验证计时，用MuJoCo正反例和录像核对接触。
2. **E2 可行性与奖励审计。** 当前奖励分量和轨迹排序、刷分压力测试；完成可行示例、标定阈值、冻结v2配置和案例。
3. **E3 短预算真实仿真奖励对照。** 先单种子排错，不作有效性结论。2048环境、batch1024、micro128，每臂64轮×32采样步=4,194,304条新交互，warmup另计；算法更新次数另报。
4. **E4 WM控制价值。** 验证事件建模与动作效果方向，在已通过的奖励/任务上比较WM与真实仿真优化；匹配真实交互预算和接口，不同时改奖励、优化器与网络结构。
5. **E5 能力扩展与协作。** 短试验通过后至少3个独立训练种子，验证固定能力图扩大、旧能力保留、跨队友与连续互传，最后K1适配和真机验证。

无可行示例、评估正反例不通过、错误轨迹刷高分、仅想象回报提升或倒地/背身增加时，不延长该方案训练；先诊断对应问题。

## 6. 选择、统计和独立验收

旧00阶段选择规则不变。下一阶段先检查有效物理与跌倒约束，再按固定全网格稳定控球达成率比较；并列按全部案例的有界完成耗时、连续保持时长、较早检查点。阈值与容差在正式训练前冻结。所有分项、未筛选末期策略和候选曲线均公开，避免选择机制掩盖退化。

每32轮开发评估、每30分钟归档；候选使用不同开发复核批次。相同初态重复、案例采样区间和训练种子差异分别报告。按预定范围测试速度/区域阈值、保持窗口和权重敏感性，结论只在窄范围成立则标记脆弱。

预留seed240000/1024不用于调参；受控新任务另生成隔离的最终案例集。配置中未填定值为null，禁止把草案冒充已接入程序的参数。
