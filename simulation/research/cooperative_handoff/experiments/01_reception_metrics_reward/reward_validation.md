# 如何验证任务与奖励设计合理

任务和奖励无法靠一条公式保证合理。用独立物理验收、反例检验、短训练和多条件复核建立证据；通过前不启动新奖励长训练。此页为实施计划，尚未通过这些检查。

## 任务与指标

| 层次 | 观察什么 |
|---|---|
| 接近与触球 | 有效触球率、首次触球位置误差和部位 |
| 接球质量 | 停球耗时、触球前后速度、相对位置 |
| 控球稳定性 | 连续控球保持时长、朝向、跌倒 |
| 完整协作 | 严格成功率、再次传出、连续交接次数 |

**停球耗时越短越好；连续控球保持时长越长越好。** 未停住不能记0秒，不能只报告成功耗时。保持使用固定接触后观察窗，球的世界末速度不能单独证明接住。

先单机器人接可重放来球，再扩大速度/偏移范围，最后验证发送方适应、角色交换与连续互传。始终保持面对面；训练课程可改变，固定全难度评估分布不变。完整任务中的发送失败也计入分母。

## 当前奖励的待验证风险

当前 `gpu_receive/model.py::reward` 主要奖励靠近身前目标与世界速度小，另有动作和姿态惩罚；没有显式接触、面对面、连续控球或再次传出。因此存在目标错配风险，**尚未证明策略利用漏洞或确定退化原因**。需分解真实轨迹的每一奖励项与物理事件，而不是只看总回报。

## 固定正反例

| 轨迹 | 必须检查 |
|---|---|
| 无接触，球因摩擦停在附近 | 不得取得有效接球事件奖励 |
| 擦碰后弹走 | 不得取得持续控球事件奖励 |
| 背身挡球、倒地压球、非目标部位接触 | 不得通过本任务面对面接球验收 |
| 只接慢球/简单球 | 全部预定案例仍反映困难案例失败 |
| 反复轻碰、出入控球区 | 同一里程碑不能重复刷分 |
| 故意倒地提前结束 | 不得靠逃避剩余时间/动作代价取得更高完整回报 |
| 接稳后一直不传 | 接球子任务可成功；完整协作不能胜过同等质量的及时交接 |
| 正常接稳并再传 | 正确触发对应事件和奖励 |

比较相同时限、折扣下完整轨迹的回报，检查奖励分量的累计上限。使用真实MuJoCo轨迹；独立任务标签不能从待检验奖励本身计算。先人工核对接触和录像，再用不显示奖励的轨迹判断核验排序；这是开发诊断，不冒充已有独立人类研究。存在合理动作成本/耗时权衡时单列，不声称任意成功轨迹都应压过任意失败轨迹。

另保留未参与权重调节的新轨迹复核，避免只对反例集调参。轨迹排序可以审计奖励，但不是正确性证明；相关工作也使用利益相关者对轨迹分布的排序检验对齐。[Muslimani等，2025](https://arxiv.org/abs/2503.05996)

## 候选奖励与接口

采用一次性稳定控制/完成交接事件、有界进度塑形、动作/姿态约束；每阶段正奖励有上限。达到控球目标后转向再传阶段，避免永久持球刷协作分。权重、阈值、时间窗保留接口，审计后再冻结。

时间代价与提前失败的终止处理必须一起检查，避免“尽早失败反而少受罚”。动作/姿态惩罚属于基础目标的权衡，不能援引塑形定理保证其不会改变行为；应通过固定轨迹排序与敏感性检查确认它们没有压过任务收益。

若用势函数塑形 `gamma*Phi(z_next)-Phi(z)`，须保持折扣一致，正确处理终止势值和包含任务历史/阶段/时间的状态。在相应MDP假设下有最优策略保持性质；不能保证基础目标正确，也不能保证近似WM和训练收敛。[Ng等，1999](https://people.eecs.berkeley.edu/~russell/papers/icml99-shaping.pdf)

接触、保持和一次性事件依赖历史。真实仿真使用接触力与任务状态机；WM想象须先验证事件预测/任务记忆接口，禁止读取未来真实事件。软代理和硬物理验收分开测量，检查误报、校准和再次被利用的风险。

## 放行条件

1. 评估器通过已知时序、失败/删失与MuJoCo接触正反例检查。
2. 最简单来球有可重现接稳示例，否则先查技能和动作权限。
3. 典型错误无法刷到对应成功奖励，完整回报排序与任务判断一致。
4. 短预算旧/新奖励对照中，独立物理指标改善，倒地/背身和失败未被掩盖。
5. 按预定范围测试阈值、保持窗和权重敏感性，不靠挑选一个精细参数获胜。
6. 再验证WM动作效果、多训练种子、跨队友与连续互传。

若训练回报升而独立任务结果降，先停止扩展该方案，诊断错配。已有研究观察到更强优化/更长训练放大奖励错配的情况，但不能据此确定本项目原因。[Pan等，2022](https://arxiv.org/abs/2201.03544)

细节见[新协议](protocol.md)和[可修改参数草案](design.yaml)。参数草案尚未接入训练，未定值为null，不表示新奖励已经生效。
