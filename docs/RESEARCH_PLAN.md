# 研究计划

2026-11-11修订：先把接球能力与奖励是否对齐测清楚，再研究世界模型驱动的协作改进。**新计划已记录，评估器和新奖励尚未实现。**

## 要解决的问题

两台机器人面对面接稳球、交换角色、连续互传。候选研究问题是：世界模型能否描述队友随学习变化的可接球范围，帮助发送方选择合适的交接条件，同时保留旧合作能力并适应未见队友？

创新论点需要机制消融、跨队友与跨条件验证。单段成功录像、位置预测误差降低或“用了世界模型”都不足以支持该论点。

## 当前证据与边界

- seed104三种处理均未稳定提高严格成功率，仍是单种子开发结果。
- 停球耗时越短越好，连续控球保持时长越长越好。旧日志测的是后者；下降不能直接证明停球变慢，也可能涉及触球、站位或朝向。
- 现有奖励强调靠近和减速，与接触、面对面、持续控制及再传出未完全对齐；这是待检验风险，尚非退化原因的因果结论。
- 当前发送方冻结，不能解释成双方学习造成的非平稳性。位置误差小也不代表动作效果预测正确。

## 新的实验顺序

| 阶段 | 工作 | 进入下一阶段的依据 |
|---|---|---|
| 0：保留旧对照 | 九组维持原协议，资源中断如实记录 | 不改写旧指标、预算和选择规则 |
| 1：评估与可行性 | 可重放来球；分别测触球、停球耗时与连续保持 | 时序/接触正反例通过，简单来球有可行示例 |
| 2：奖励合理性 | 旧奖励分解、轨迹排序、刷分反例、短预算旧/新奖励对照 | 独立物理指标改善，失败和姿态问题未被掩盖 |
| 3：WM控制价值 | 接触误差、真实动作扰动、WM与真实仿真优化对照 | 真实控制改善，不能仅提高想象回报 |
| 4：能力范围 | 速度×偏移能力图，扩大训练条件 | 固定全网格、多种子支持能力扩大与旧能力保留 |
| 5：合作扩展 | 发送方适应、双方更新、角色交换与连续互传 | 跨队友、连续交接、扰动与独立集验证 |

先测单机器人接可重放来球，分离发送方失误；受控测试和完整任务分别报告，保持面对面。训练可以由易到难，评估保留固定完整难度分布。

## 四层指标

| 层次 | 独立记录 |
|---|---|
| 接近与触球 | 有效触球率、首次触球位置误差与部位 |
| 接球质量 | 接触到控制的耗时、触球前后球速、相对位置 |
| 控球稳定性 | 固定窗口连续保持时长、朝向误差、跌倒率 |
| 完整协作 | 严格接球率、再传出率、连续2/5/10次交接率及次数 |

耗时连同失败率和分母报告，未停住不能记0秒；保持使用相同观察窗。自然滚停、慢来球和无触球单列。严格成功率继续用于最终验收，早期不再作为唯一学习进展依据。

下一阶段先检查物理有效性与跌倒约束，再按固定全网格稳定控球达成率、全部案例的有界完成耗时等选择；独立开发批次复核，公开所有候选与末期曲线。旧对照选择规则不变。

## 奖励合理性与训练安排

验收独立于训练奖励。自然滚停、擦碰弹走、背身挡球、倒地压球、重复轻碰和永久持球不能刷到不应有的成功奖励；然后做短预算真实仿真训练及阈值/权重敏感性检查。通过后才增加预算和协作复杂度。

奖励、任务记忆与WM事件预测接口一起核验，想象中不能读取未来真实接触。2048环境/batch1024/micro128作为新阶段短试验起点；当前先恢复原对照，新增GPU任务通过前置检查后串行排入，不抢占其他进程。

操作定义与工程参数见[新协议](../simulation/research/cooperative_handoff/experiments/01_reception_metrics_reward/protocol.md)，放行条件见[奖励验证](REWARD_VALIDATION.md)。工程初值须在训练前标定并冻结，不当作已验证标准。

## 架构与论文证据

保留物理WM、原生技能与显式控制器记忆。先证明任务可学、奖励对齐、模型对控制有用，再增加队友能力与交接状态表示。比较普通条件输入、等容量critic/WM和交接模型，验证额外结构的作用。

至少三个独立训练种子；跨队友checkpoint、旧能力保留与连续交接分别验证。G1用于机制原型，K1单独做技能适配、感知/延迟标定和真机验证。相关工作边界见[文献表](../simulation/research/cooperative_handoff/literature/survey.md)。
