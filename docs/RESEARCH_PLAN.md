# 研究计划

## 要解决的问题

一台机器人将球送入另一台可接稳、可继续传出的状态。若队友技能更新，原来学到的交接条件可能不再合适。研究目标是让模型描述这种能力变化，并用真实交互验证更新是否带来持续的协作提升。

传接球是验证任务。论文论点应来自可检验的机制、跨队友和跨条件泛化，而不是单段成功录像或“用了世界模型”。

## 当前证据与边界

- 历史训练曾出现开发集成功率先升后降，但存在控制过程和回报统计不一致。
- 历史发送方冻结，只训练接收方，不能据此宣称“双智能体共同学习造成退化”。
- 位置预测误差小，不代表动作对接球结果的影响方向正确。
- 世界模型/策略共同迭代、多智能体预测、技能衔接、足球技能均已有近邻工作，见[文献表](../simulation/research/cooperative_handoff/literature/survey.md)。

## 三个阶段

1. **可信基线。** 固定初态和成功判据；复测历史检查点；对齐执行与想象中的控制器时序、历史与阶段；统一回报。分别报告修复前后结果。
2. **机制诊断。** 在固定真实轨迹上测接触前后预测；比较保持/记录/闭环发送方；再用真实扰动检查动作收益的排序与梯度方向。只有模型对控制有用，才继续加复杂度。
3. **合作扩展。** 引入队友能力与交接条件表示；交替或共同更新双方；测试旧队友保留、未见队友、连续多次互传与真实物理参数变化。

## 候选架构

保留物理世界模型与原生低层技能，显式携带低层控制器记忆。后续增加队友能力条件及交接状态表示，预测“现在把球交过去后，对方能否接稳并继续传出”。训练使用自身采集的数据，按固定开发集检查候选更新；同时公开候选本身和被接受策略的表现，避免用选择机制掩盖退化。

先比较等容量 critic、普通多智能体 WM、队友 checkpoint 条件、交接条件模型，再判断额外结构是否值得保留。能力表示与训练目标尚未定型，必须由前两阶段证据决定。

## 什么算成功

- 修复后的基线在相同真实交互预算下可重复；完整报告峰值与末期表现。
- 机制改进超越普通条件输入/等容量网络，提升真实成功率和连续传球次数。
- 多次独立续训、跨队友验证和物理参数变化支持结论。
- K1 真机阶段验证感知、通信、控制延迟和模型差异；G1 权重不直接迁移。

若只得到更好的录像、只降低状态 RMSE，或仅靠拒绝更新保住旧成功率，则不足以支撑目标论点。1–2 周先导实验用于判断是否值得继续投入，不承诺论文录用或真机达标时间。
